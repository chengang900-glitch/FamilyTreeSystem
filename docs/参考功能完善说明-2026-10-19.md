## 本轮新增反馈

| 用户反馈 | 已实现行为 |
|---|---|
| 日期输入不便，也不利于统计 | 成员生卒、婚姻结离、事件日期使用中文公历选择器；可选完整日期、仅年月、仅年份或农历/历史文字。日期原文保留，另存 ISO 值和精度，提供统计索引；不为未知月日补造日期，也不把农历自动视作公历 |
| 选择 A 后 B 不应再出现 A | 婚姻双方的选择器互相排除已选人员 ID，后台仍拒绝双方相同的提交；同名不同人的记录不会被误删 |
| 婚姻本段次序允许重复 | 按用户确认的规则，以“本谱＋成员 A＋本段次序”检查重复；新增、编辑、导入和并发写入均受保护，编辑排除自身。不同 A 可以分别拥有第 1 段 |
| 成员新增联系/任职信息 | 增加住址 `address`、手机号 `phone`、单位/公司 `company`、职位 `position`；支持表单、列表/卡片、读写、审计、隐私脱敏、JSON/CSV/GEDCOM 扩展往返、备份及付印 |
| 亲子不能只选“父/母” | 表单分别选择父亲、母亲，逐个子女指定与双方的关系，一次提交以事务保存。再婚时明确指定本批子女的母亲，不自动追加父亲所有配偶；身份不详时允许留空一方 |
| 父亲、母亲按成员类型限制 | 父亲只选宗男/姻婿/外孙，母亲只选宗女/姻媳/外孙女；服务端筛选后再分页，搜索沿用相同限制；保存时再次校验当前类型，类型错误整批拒绝。子女类型不受此限制，已有关系不自动修改 |

## 数据与升级行为

- 新版本启动时，自动检查并补齐字段。旧库需要补列时，先在备份目录生成 `before_profile_日期时间.db`，再进行事务迁移；重复启动不重复补列，多进程持锁后再次检查列。
- 现有日期原文不会被替换。规范公历值回填到 `birth_date_iso` / `death_date_iso` / `marriage_date_iso` / `divorce_date_iso` / `time_iso`，对应 `*_precision` 为 `day`、`month`、`year`、`text` 或空值。历史文字日期的 ISO 为空。
- 新录入的非法公历日期会被拒绝；未更改的旧非标准日期仍可保留。日期先后仅在区间确定颠倒时拒绝。
- 联系字段和日期统计字段不能绕过成员隐私规则。导入会按原始日期重算统计字段，不信任文件中伪造的 ISO 值。
- 旧重复婚姻不会自动删除或改号；需要人工核对后修改。新保存或导入的冲突会返回明确错误并回滚。
- 此前“同一成员三段婚姻均用次序 1”的回归样例已按用户确认的新规则改为 1/2/3；没有删掉多段婚姻用例。
- GEDCOM 的 `_FTS_*` 扩展用于本系统字段保真，其他软件可能忽略。完整迁移仍应选 JSON/ZUP 并包含资源原件。
