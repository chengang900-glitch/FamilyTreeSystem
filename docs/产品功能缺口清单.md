## 二、仍然存在的缺口

### P1：需要产品确认的边界

| 缺口 | 现状 | 建议 |
|---|---|---|
| ZUP 与原型包兼容 | 已实现自洽 `.zup`，但没有原型 ZUP 样例，无法证明与桌面版格式一致 | 提供原型“刘氏家谱”ZUP 包做导入/导出闭环验收；必要时按原型结构适配 |
| 全库恢复的产品化 | 已有离线脚本，但无 Web 维护模式/恢复任务 | 若要求页面内恢复，需要维护模式、停写、任务进度与失败回滚设计 |
| 旧数据/旧客户端兼容 | 刷新令牌上线后旧会话需重新登录；ZUP 是新格式 | 升级说明中标注；旧 Cookie 过期后重新登录即可 |

### P2：体验与性能

| 缺口 | 现状 | 建议 |
|---|---|---|
| 长列表虚拟滚动 | 资源缩略图已 lazy 加载；表格未启用虚拟滚动 | 大列表可加 `virtual` + 固定行高 |
| 深浅主题细节 | 基础深色主题已切换；部分页面仍有硬编码浅色装饰 | 清理硬编码色值 |
| 上传上限 | `storage.upload_max_mb` 受 `config.yaml upload.max_mb` 全局 200MB 限制 | 统一为一个上限来源，前端显示实际生效值 |
| 资源备份体量 | ZIP 导入/导出仍有内存峰值 | 进一步流式化/临时文件化 |
| 管理后台列表 | 用户/家谱/日志仍是单一表格视图 | 如需与业务列表一致，可补列设置/卡片视图 |

### P3：字段语义与文档

| 缺口 | 现状 | 建议 |
|---|---|---|
| `visibility` | 字段保留，UI 已移除；公开只读未实现 | 保持“仅成员”并删除字段，或真正实现可见性 |
| 最近项目 | 无 | 可加“最近家谱” |
| 农历/公历互转 | 仅文本双记 | 方案明确二期 |
| 公开只读/member.scope/邀请码/PWA | 未实现 | 方案已明确本期不做或二期 |
| 操作日志保留期 UI | 设置项已加，但 `0=永久` 的风险提示较弱 | 在设置页描述中强调；生产环境建议设置 365 天等 |
