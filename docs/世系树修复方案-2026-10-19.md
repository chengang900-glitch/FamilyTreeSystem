# 世系树修复方案（已确认并实施）

本文件保留方案形成时的问题分析与约定。用户随后确认实施并部署；另追加亲子编辑、男女统一人工排行及成员列表分支列宽调整。实际结果见[修复验收记录](世系树与亲子编辑验收-2026-10-19.md)。截图中的实际亲属归属不能仅凭曲线推断。

## 1. 已确认的问题

| 现象 | 代码原因 |
|---|---|
| 第二代、第三代的配偶出现在祖辈一层 | `layoutTree` 把没有父母记录的成员当作另一棵树的根，统一从深度 0 开始；排位不利用配偶关系 |
| 看不出谁与谁结婚，子女属于哪对父母 | `edgesOf` 只生成亲子边，`spouses` 未参与布局或画线；父母分别向孩子拉长线 |
| 线贴在卡片上边、穿过卡片或重叠后难分辨 | 所有边都从卡片上沿中点连到另一张卡片上沿中点；横纵共用同一条贝塞尔路径公式，没有端口和避障 |
| 并排式选“纵向”仍按列展开 | 该布局不接收方向参数，方向选择对它无效 |
| 图较小、留白大，缩放比例不直观 | 人为设定最小图幅，再使用 SVG viewBox 与内部 scale 双重缩放；适应画布没有统一的实际像素变换 |
| 生养类型无法在树中辨认 | 接口查询了亲子类型，却在响应中只返回父母/子女 ID；婚姻也只保留配偶 ID，未提供关系 ID 与次序 |

使用合成四代七人样例直接执行当前算法：第二代母亲、第三代配偶均被放到纵向 `y=0`，与第一代同层；切换并排式横纵方向得到完全相同坐标。样例仅用于复现算法，不代表生产中的具体关系。

此前五种布局检查仅覆盖成员集合、节点坐标唯一性和直系筛选；没有验证夫妻位置、边的含义、穿卡、家庭分组或实际可读性，因此不能继续将这些检查通过视为世系图验收通过。

## 2. 方案选择

1. 只增加间距、修改颜色和曲率：改动较少，但无法解决双亲、多段婚姻和配偶被当成独立根的问题，不推荐作为主方案。
2. **按家庭关系重做布局与连线：推荐。** 保留现有页面及人员卡片，补足关系数据，重做树形与并排式的排位、连线及视图变换。
3. 整体替换为通用图编辑组件：仍需自行定义家谱规则，且增加依赖和迁移范围。先通过本项目样例验证家庭布局方案，出现明确能力缺口后再评估。

## 3. 推荐的显示规则

### 3.1 人员、婚姻、亲子分开表达

- 人员仍对应原成员 ID，正常视图中不重复绘制同一成员，也不复制业务记录。
- 婚姻用夫妻连接线表达，婚姻次序沿用成员 A 的排序规则；不能把该排序当作双方统一的婚姻次序。
- 为实际的一组共同父母设置内部连接点，再从该连接点分叉到对应子女。连接点只参与绘图，不是数据库新增人员，也不计入族人数。
- 共同父母不一定登记过婚姻：没有婚姻记录时，仅表达共同父母关系，不伪造夫妻线。
- 只知道一方时，直接从该父/母连到子女；不补造“未知父亲/母亲”成员。
- 同父异母或同母异父的子女按实际父母组合分组。绝不把某人的全部配偶自动当成所有孩子的父母。
- 同一子女有亲生、收养、过继等多组关系时，保留各条真实关系，明确标注类型；不能随意选两个人组成夫妻。无法确定唯一组合时使用独立关系线，不擅自配对。

### 3.2 层级与排序

- 亲子关系约束上下层级；登记世代用于排序和一致性核查。配偶即使未登记父母，也跟随自己的家庭定位，不能默认升到第一代。
- 正常家庭中夫妻相邻、处于同一辈层，兄弟姐妹并列，共同父母居于其子女组上方；横向时对应旋转布局方向。
- 为每个家庭及其后代预留空间，不能只按某一父亲递归排完，再把母亲补到一旁。
- 排序稳定：使用已有世代、关系顺序和 ID 等明确规则，不推断未知长幼。切换方向或刷新时尽量不改变兄弟姐妹相对顺序。
- 选择主人物用于定位和确定查看范围；全谱模式不能把所选成员的祖先挤到后代位置。
- 无关联人员单独成组展示，不冒充共同祖先。
- 对世代矛盾、同一子女多条同类父母关系等情况提示核对，保留原数据，不自动改世代或删关系。跨代婚姻等复杂情况保留真实连线，不强行合并层级。

### 3.3 连线

- 纵向：从父母/家庭组底部向下，经分叉线到子女卡片顶部。
- 横向：从父母/家庭组右侧向右，经分叉线到子女卡片左侧。
- 夫妻线与亲子线使用不同的线型与位置，并提供简短图例，不能仅靠颜色区分。
- 亲生采用实线；收养、过继、继养等显示类型标签或不同线型，具体含义与现有亲子类型一致。
- 折线采用轻微圆角。端点固定在卡片边缘，预留走线通道，不穿过人员卡片。
- 简单家庭样例不得交叉。复杂互婚无法保证零交叉时，用清楚的独立走线和关系高亮保持可追踪性，不承诺任意图都能零交叉。

### 3.4 视图与导出

- 默认首先修好纵向树形，横向使用相同家庭结构和方向变换。
- 并排式按家庭排序，并真正响应横纵切换。其余三种布局共用明确的关系数据与线型；不适用的方向操作应禁用或隐藏，不能继续保留无效控件。
- 统一一套画布坐标与缩放变换；按实际节点和连线路径的完整包围框计算居中和适应，不叠加两套缩放。
- 适应全图时允许合理留白，但不能为填满屏幕而把小图无限放大；大图全览可能缩小文字，保留清楚的 100% 查看及缩放入口。
- 点选人员时高亮其配偶、父母、子女及相关线，其他关系适当淡化；保留现有详情入口。
- “只看直系”沿用实际祖先/后代集合，不将配偶冒充直系。因筛选只显示一方父母时，仅画可见关系，不留下悬空线。人数显示当前可见人数及全谱总人数。
- PNG/JPG/SVG 复用同一排位和连线数据，导出包含线型图例及完整路径范围，不受当前拖动位置影响，不截断边缘线或标签。

## 4. 最小技术改动范围

- `server/blueprint/pedigree_bp.py`：保留现有节点结构，另返回本谱婚姻、亲子关系明细，包括关系 ID、人员 ID、亲子类型及婚姻次序。继续沿用现有访问权限与隐私规则。
- `web/src/pedigree/layout.ts`：由人员递归树改为人员、家庭连接点与类型化边的布局结果；统一方向、端口、包围框及稳定排序。
- `web/src/pages/Pedigree.tsx`：按边类型绘制，统一缩放/居中，补图例和关系高亮；导出共用绘图结果。
- `scripts/test_layout.mjs` 及世系接口相关回归：新增具有明确关系预期的样例与几何断言。

当前数据表已保存婚姻和亲子类型，此方案优先不改表结构，不改写现有人员、婚姻或亲子记录。实施中如发现必须扩展数据语义，应单独列出原因和范围再讨论。

## 5. 实施及验收顺序

1. **先建立关系样例** → 验证：四代七人、双亲兄弟姐妹、再婚、单亲、亲生加收养、独立成员均有明确预期；截图库关系只在核对原始关系后使用。
2. **补齐接口关系数据并实现家庭布局** → 验证：夫妻相邻、亲子层次正确、同父异母子女不串组、人员无遗漏或重复、原数据未修改。
3. **修复横纵连线与画布** → 验证：横纵端口正确、卡片矩形无重叠、非关联线不穿卡、简单家庭无交叉，方向切换与 100% 比例有实际效果。
4. **浏览器与文件验收** → 验证：逐项检查五种布局的适用行为、直系过滤、缩放拖动、关系高亮及三种导出；对比实际截图和导出文件，不能只看坐标测试。
5. **方案确认后再部署** → 验证：备份并保留运行数据；在开放公网前完成不受同时业务写入影响的版本与数据核对，再检查真实入口。

第一轮实现以“能明确判断谁与谁是夫妻、每个孩子属于哪些父母”为主，不增加节点拖动保存、复杂图形编辑或新业务字段。
