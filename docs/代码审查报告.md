# 家谱管理系统（Web 版）代码审查报告

- 审查日期：2026-10-18
- 审查范围：`server/`（21 个 Python 文件，约 2,700 行）、`scripts/`（5 个自测脚本）、`web/src/`（22 个 TS/TSX 文件，约 3,675 行）、`deploy/`、`web/vite.config.ts`、`web/package.json`、`DEPLOY.md`、`docs/产品开发方案.md`
- 未覆盖：`web/node_modules`、`server/webroot` 构建产物逐行审计
- 审查方式：静态阅读 + 隔离库实测（探针脚本，独立配置指向临时库，未改动项目业务代码与 `data/app.db`）
- 实测环境：Python 3.13.14 / Flask 3.1.3 / PyJWT 2.15.1 / ReportLab 5.0.1；Node 22 + React 19 + antd 6 + Vite 8

> 标注说明：**【实测】**表示已在隔离库中复现并记录实际响应；**【审查】**表示由代码路径推断，未单独运行验证。

---

## 一、结论摘要

架构方向正确：三层鉴权（登录 / 超管 / 家谱角色）在后端强制落地，写操作有 `assert_in_family` 二次归属校验，SQL 全部参数化（仅表名、列名走内部白名单），密码使用 scrypt，审计表覆盖写操作，备份使用 SQLite 官方 backup API。这些是真实存在的有效设计，不是"看起来有"。

主要风险集中在三处：**交付链路不可用**、**错误处理与数据一致性**、**安全边界的实现漏洞**。

| 级别 | 数量 | 影响 |
|---|---|---|
| P0 阻断 | 5 | 按文档无法构建/启动服务；脏数据可长期累积 |
| P1 高危 | 9 | 认证绕过辅助、信息泄露、安全配置形同虚设 |
| P2 中危 | 16 | 500 错误、导入关系错乱、缓存与备份在多进程下失效 |
| P3 建议 | 8 | 死代码、依赖多余、构建上下文与类型检查缺失 |

与《产品开发方案》§十三「M1–M8 全部完成、111 项检查全通过」的表述存在偏差：部分承诺能力（公开只读、在世者脱敏、家谱级日志、备份恢复）并未实现，或实现范围小于权限矩阵。

## 二、P0 阻断级

| # | 位置 | 问题 | 证据 |
|---|---|---|---|
| 1 | `web/package.json` | **没有 `build` 脚本**，只有 `test`；而 `DEPLOY.md` §2/§3 与 `deploy/Dockerfile` 均执行 `npm run build` | 【实测】`npm run build` → `npm error Missing script: "build"`。现有 `server/webroot` 产物应是用 `npx vite build` 之类方式生成的，与文档不一致 |

| 3 | `deploy/Dockerfile:15` | `FTS_CONFIG=/app/data/config.yaml`，但镜像内与 compose 卷中都无此文件 | 【实测】以该路径启动 → `FileNotFoundError: ... /app/data/config.yaml`，容器启动即崩 |

## 三、P1 高危（安全）

| # | 位置 | 问题 | 证据与后果 |
|---|---|---|---|
| 6 | `app.py:132,140-145` | 限流 IP 取自 `X-Forwarded-For` 首段且无代理白名单；`_rate_bucket` 为进程级字典，**永不清理** | 【实测】150 次请求各带不同伪造 XFF，全部 200，桶数量涨到 152。等于限流可绕过，同时可被刷爆内存（无上限字典） |
| 7 | `family_bp.py:501-510` | `/api/families/user-search` 仅需登录，**跨家谱**返回全站账号、真实姓名、手机号；该接口前端未使用（死接口） | 【实测】普通用户命中 `{'username': 'admin', 'real_name': '超级管理员'}` |
| 8 | `auth_bp.py:86-101` | 改密成功后未 `token_version+1`，旧令牌继续有效 | 【实测】改密 200，拿改密前的 Cookie 访问 `/api/auth/me` 仍 200。密码泄露后改密无法踢人 |
| 9 | `app.py:161-169`、`auth_bp.py:12-25` | `must_change_pwd` 只在前端 `Login.tsx` 提示一次，后端从不拦截 | 【实测】超管重置密码后（flag=True），该用户直接调 `/api/families/<fid>/persons` 返回 200 |
| 10 | `app.py:161-169`、`web/src/pages/Login.tsx:57-62` | 初始化默认口令 `admin/admin123` 硬编码并打印到 stdout；登录页用 Alert 公开展示该口令 | 【审查】公网部署时等于公布后台入口的默认凭据。配合 #9，该口令可能长期存在 |
| 11 | `family_bp.py:93-109` | 家谱管理员可通过 `POST /api/families/<fid>/members` 给他人授予 `role=admin` | 【实测】管理员 A 给 B 授 admin → 200，库内角色为 `admin`。与方案 §2.2「指派/取消家谱管理员：家谱管理员=否」冲突，属横向提权 |
| 12 | `family_bp.py:86-90` | 家谱成员名单对所有家谱成员返回 `phone` | 【实测】返回他人手机号 `13800000000`。属最小权限问题，普通成员无需看到手机号 |
| 13 | `app.py:76-84` | `after_request` 对**所有**响应下发 `Cache-Control: no-cache, no-store` | 【实测】`/assets/index-B5BXDqMa.css` 带 `no-store`。1.27 MB 单文件 JS 每次刷新重下，同时使 `nginx.conf` 的 `expires 7d` 完全失效 |
| 14 | `service/settings.py:9-36`、`web/src/pages/admin/Settings.tsx` | `access.public_read`、`privacy.mask_living`、`member.scope` 在设置页可开关，但全项目 **0 处读取**；`constants.ts:22 maskPerson()` 亦无调用 | 【实测】`grep` 无引用。访客公开只读路由不存在；在世者脱敏不生效。用户以为已开启，实际无效——比没有更危险 |

补充残留风险：`_csrf_check`（`app.py:148-158`）在无 `Origin` 头时直接放行，现行防线实际只有 `SameSite=Strict`；无 CSP 头。

## 七、修复顺序建议

### 批次 1：让交付链路可用（P0，优先于一切功能）
1. `web/package.json` 补 `dev` / `build` / `typecheck` 脚本；`build` 统一 `vite build`。
2. 统一前端产物目录：要么 `vite.config.ts` 改回 `dist` 并在 Dockerfile 复制，要么 Dockerfile 改为复制 `/server/webroot`（二选一，不要两套约定）。
3. 容器配置注入：把 `server/config.yaml` 复制为 `/app/config.yaml` 并令 `FTS_CONFIG` 指向它；需要改参数时用挂载覆盖，而不是依赖 `/app/data/config.yaml` 存在。
4. `deploy/start.bat` 改为 `cd /d "%~dp0.."`。
5. 验证：`cd web && npm ci && npm run build`；`docker compose -f deploy/docker-compose.yml build`；容器内 `curl -f localhost:8000/api/health`；Windows 双击 `start.bat` 能起服务。

### 批次 2：安全边界（P1）
6. 限流：只信任来自受控代理的 XFF（按 `remote_addr` 在允许列表内才读 XFF）；`_rate_bucket` 增加定期清理或改用固定窗口计数。
7. 下线 `/api/families/user-search`；成员搜索限定在当前家谱且要求 `admin`。
8. 改密/重置成功后 `token_version = token_version + 1`，并同步刷新当前 Cookie。
9. `must_change_pwd=1` 时，除 `/api/auth/me`、`/api/auth/password`、`/api/auth/logout` 外一律 403。
10. 首次启动生成随机口令（或强制首登改密 + 后端拦截），删除登录页默认口令提示。
11. `member_add` 的 `role` 收窄为 `member`，授 `admin` 仅走超管接口。
12. `member_list` 对 `member` 角色隐去 `phone`；`/members` 路由按角色收紧。
13. `no-store` 仅用于 API 与 HTML，静态资源改 `public, max-age=31536000, immutable`（文件名已带 hash）。
14. 三个死配置二选一：实现（公开只读路由 / 脱敏中间件）或从设置页与 DEFAULTS 中移除。

### 批次 3：数据正确性（P2）
15. 统一入参校验层（`generation`/`type`/分页/上传 `type`/婚姻双方），非法值返回 400；`branch_id` 空串统一转 `None`。
16. 引入 `with transaction():` 上下文（`BEGIN IMMEDIATE`），包裹 `delete_family`、`branch_update`、`create_family`、`import`、`person_delete`。
17. 补外键：`person.branch_id`、`marriage.spouse*`、`parentchild.*`、`eventperson.*`、`resource_relation.*`；删除时按 `ON DELETE CASCADE/RESTRICT` 明确语义（注意 SQLite 需在每连接启用 `foreign_keys`）。
18. 亲子关系加环检测（写入前 DFS 检查祖先链）。
19. 导入实现 ID 重映射表（旧 ID → 新 ID），并解包 ZIP 内 `resources/`；`INSERT` 计数改用 `cur.rowcount`。
20. 备份：仅主进程启动线程（或加文件锁）；时间戳加毫秒/pid；失败改为 `logger.exception` 并在超管界面提示。
21. 设置缓存加 TTL（如 30s）+ 写后广播失效（或改读 DB 缓存表）。
22. 测试隔离：`scripts/*` 启动前设置 `FTS_CONFIG` 指向临时目录，并断言连接的是测试库。
23. `tsc --noEmit` 纳入构建；修 `JSX` 命名空间、补 `*.css` 声明、`TouchList` 类型。

### 批次 4：工程质量（P3）
24. 加 `.dockerignore`（`node_modules`、`data`、`.venv`、`log`、`server/webroot`）。
25. 配置 `logging`（文件 + 轮转），与 `DEPLOY.md` 表述一致。
26. 清理死接口/死代码与未使用依赖；补数据库迁移脚本；`operation_log` 加保留策略。
