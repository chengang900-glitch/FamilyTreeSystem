# 产品功能补齐说明（2026-10-18）

本轮按《产品功能缺口清单》的批次 A/B 及部分批次 C 实施，重点补齐权限矩阵、数据交换、审计与设置接线。

## 一、新增能力

### 1. JWT 刷新令牌

- 访问令牌固定 `security.session_hours`（默认 8h）；
- 刷新令牌 `security.refresh_days`（默认 7d，`remember` 时使用持久 Cookie）；
- 新增 `POST /api/auth/refresh`，不要求访问令牌仍有效；
- 登出、改密、重置密码通过 `token_version` 使旧访问/刷新令牌一起失效；
- 前端 `api.ts` 在 401 时自动刷新一次并重试原请求；
- 刷新 Cookie `path=/api/auth`，降低暴露面。

**兼容性**：升级后旧会话在访问令牌过期时需重新登录一次；旧访问令牌（无 `typ`）仍按 access 处理。

### 2. 家谱级日志

- `GET /api/families/<fid>/logs`：家谱管理员/超管查看本谱日志；
- `GET /api/families/<fid>/logs/export`：CSV 导出；
- `GET /api/admin/logs/export`：超管全站日志导出；
- 新增前端“本谱日志”页；普通成员访问返回 403。

### 3. 家谱级备份/恢复

- `GET /api/families/<fid>/backup`：数据 + `manifest.json` + `data.json` + `resources/`；
- `POST /api/families/<fid>/restore`：校验 manifest 后覆盖恢复本谱数据、元数据与资源；
- 前端“备份与恢复”页；恢复前二次确认；
- 超管额外可下载全库备份：`GET /api/admin/backups/<name>`；
- 全库恢复新增离线脚本 `scripts/restore_backup.py`（停服、完整性检查、保留旧库、清理 WAL）。

### 4. ZUP 数据交换

- 导出 `format=zup`，产出 `.zup`（ZIP：`manifest.json` + `data.json` + 可选 `resources/`）；
- 导入 `.zip`/`.zup` 自动识别 `data.json`，不再误选 `manifest.json`；
- 前端“数据交换”增加 ZUP 选项。

> 说明：当前实现是自洽的 ZUP 格式；与桌面版原型 ZUP 的字段/目录兼容性仍需原型样例做验收。

### 5. 审计

- update 类操作记录结构化 JSON：`{字段: {old, new}}`；
- 新增 `storage.operation_log_retention_days`（0=永久），每次备份后清理过期日志；
- 本谱/全站日志 CSV 导出；
- 家谱日志页会把 JSON 变更摘要渲染为“字段: 旧值 → 新值”。

### 6. 设置接线

- `/api/auth/me` 新增：`password_min_length`、`password_require_strong`、`default_strategy`、`upload_max_mb`；
- 新增公开 `/api/site` 返回站点名；
- Persons 使用 `site.page_size`；
- DataExchange 使用 `storage.default_strategy`；
- Profile/Users 密码规则使用系统设置；
- Login 使用站点名；
- Resources 使用实际上传上限（不超过全局 `MAX_CONTENT_LENGTH`）并增加移动端 `capture`。

### 7. 其他

- 婚姻离婚日期：两端均为 `YYYY-MM-DD` 时校验“离婚 ≥ 结婚”；
- 世系图导出边距可调（0–200px）；
- 资源上传增加移动端拍照提示与前端大小校验；
- README 的“CSV 批量导入导出”修正为“CSV 导出”（导入仍为 JSON/GEDCOM/ZIP，符合产品方案）；
- 修复 ZUP/备份包中 `manifest.json` 早于 `data.json` 导致导入 0 条的问题。

## 二、行为变化

1. `remember` 不再把访问令牌延长到 7 天；访问令牌固定 8h，刷新令牌 7d。
2. 家谱备份恢复会**覆盖本谱全部业务数据和资源**，入口已加二次确认。
3. ZUP 是本系统定义的交换包；原型兼容性待样例验收。
4. 操作日志保留期默认 0（永久）；设置大于 0 后仅在备份成功后清理。
5. 普通成员仍不能查看本谱日志/备份，只有家谱管理员和超管可用。
