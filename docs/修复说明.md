## 二、批次 1：交付链路（P0）

### 1. 前端没有 build 脚本，文档里的构建命令直接失败

**问题**：`web/package.json` 只有 `test` 脚本，`DEPLOY.md`、`Dockerfile` 却都执行 `npm run build`。

**修改**（`web/package.json`）：

```json
"scripts": {
  "dev": "vite",
  "build": "npm run typecheck && vite build",
  "build:fast": "vite build",
  "typecheck": "tsc --noEmit",
  "preview": "vite preview"
}
```

顺带把类型检查并入 `build`，让「类型不通过」在构建阶段就暴露，而不是被 esbuild 跳过。

**验证**：`cd web && npm run build` 输出 `../server/webroot/index.html` 与 `assets/`。

### 2. Dockerfile 取产物路径与 Vite 输出路径不一致

**问题**：Vite `outDir` 是 `../server/webroot`，Dockerfile 却 `COPY --from=web /web/dist/`。

**修改**（`deploy/Dockerfile`）：改为 `COPY --from=web /server/webroot/ ./server/webroot/`，
并在注释里写明这个对应关系，避免以后又出现两套约定。

### 3. 容器启动即崩：配置文件不存在

**问题**：`FTS_CONFIG=/app/data/config.yaml`，镜像与卷里都没有这个文件。

**修改**（`deploy/Dockerfile`、`deploy/docker-compose.yml`）：

- 镜像内 `COPY server/config.yaml ./config.yaml`，`FTS_CONFIG=/app/config.yaml`；
- 需要自定义参数时，把配置文件挂载到 `/app/config.yaml` 覆盖（compose 里已留注释行）。

**验证**：以 `/app/config.yaml` 方式启动可正常读配置（本地用等价路径复现通过）。

### 4. `start.bat` 在 `deploy/` 下找 `.venv`

**问题**：`cd /d "%~dp0"` 后查找 `.venv\Scripts\python.exe` 与 `server\requirements.txt`。

**修改**（`deploy/start.bat`）：`cd /d "%~dp0.."`，并补错误分支与「前端未构建」提示。

### 5. 全库零外键，脏数据可长期累积

**问题**：`PRAGMA foreign_keys=ON` 没有实际约束，删人物留下 `eventperson` 孤儿，
导入可写入 `spouse2_id=999999` 这类悬空引用。

**修改**：

- `server/db/schema.sql`：为核心表补外键（新库直接生效）
  - `family_id → family(id) ON DELETE CASCADE`
  - `eventperson → event/person`、`resource_relation → resource`：`ON DELETE CASCADE`
  - `marriage.spouse* / parentchild.*`：`ON DELETE RESTRICT`（应用先给可读提示）
  - `person.branch_id / event.branch_id / branch.parent_id`：`ON DELETE SET NULL`
- 新增 `server/db/migrate.py`：旧库启动时按 SQLite 官方流程
  「建新表 → 拷数据 → 删旧表 → 改名」重建 9 张表，全程一个事务，异常整体回滚；
  迁移前先清理无法满足约束的脏数据（悬空引用、唯一键重复、非法枚举值、空串外键）。
- 应用层兜底：`person_delete` 显式清理 `eventperson` / `resource_relation`，
  `event_delete` / `branch_delete` 同理。

**验证**：

- 在**生产库副本**上注入脏数据后启动：悬空婚姻被删 1 行、孤儿 `eventperson` 被删 1 行、
  `branch_id` 空串/悬空值被置空 3 处，有效数据行数与索引全部保留，
  `PRAGMA foreign_key_check` 为空；二次启动不再触发迁移（幂等）。
- 回归用例：`悬空 spouse_id 被外键拦截`、`删除人物后无 eventperson 孤儿`。

## 三、批次 2：安全边界（P1）

### 6. 限流可被伪造 XFF 绕过

**问题**：IP 直接取 `X-Forwarded-For` 首段；`_rate_bucket` 永不清理。

**修改**：

- 新增 `server/service/netutil.py`：只有 `remote_addr` 属于受信代理（`security.trusted_proxies`，
  默认 `127.0.0.1,::1`，支持 CIDR，可用 `FTS_TRUSTED_PROXIES` 覆盖）时才读 XFF。
- `server/app.py`：限流只作用于 `/api/*`；每 60 秒清扫一次空闲超过 120 秒的桶；
  加锁避免多线程竞争。
- `server/service/audit.py` 的 IP 同步改用同一函数。

**验证**：同一 `REMOTE_ADDR` 携带 150 个不同伪造 XFF 请求登录接口，第 4 次即 429（限流阈值调为 3）。

### 7. 账号枚举接口 `/api/families/user-search`

**修改**：删除该接口（前端从未调用）；成员搜索接口保留但要求家谱管理员角色，结果限定在当前谱。

**验证**：`GET /api/families/user-search` 返回 404。

### 8. 改密后旧令牌仍有效

**修改**（`server/blueprint/auth_bp.py`、`server/service/auth.py`）：

- 改密成功后 `token_version + 1`，并用新版本重新签发 Cookie 给当前会话；
- 新增 `auth.set_auth_cookie()` / `auth.bump_token_version()`，登录、改密、登出共用一套逻辑。

**验证**：保存改密前的 Cookie，改密后访问 `/api/auth/me` 返回 401；当前会话仍 200；新密码可登录。

### 9. `must_change_pwd` 只有前端提示

**修改**（`server/app.py`）：`before_request` 中判断，未改密时除
`/api/auth/me`、`/api/auth/password`、`/api/auth/logout`、`/api/health` 外一律返回
`403` + `code=4031`；前端 `api.ts` 收到 4031 自动跳转个人中心。

**验证**：重置密码后直接调业务接口 → 403/4031；`/auth/me` 仍 200；改密后恢复。

### 10. 默认口令 `admin/admin123` 硬编码

**修改**（`server/app.py`、`web/src/pages/Login.tsx`）：

- 首启口令取 `FTS_ADMIN_PASSWORD`，未设置则 `secrets.token_urlsafe(12)` 随机生成，
  仅在控制台打印一次，`must_change_pwd=1` 强制首登改密；
- 登录页删除「默认账号 admin / admin123」的公开提示。

**验证**：全新库启动输出随机口令；用该口令登录后业务接口被 4031 拦截。

### 11. 家谱管理员可授予他人 `admin`（横向提权）

**修改**（`server/blueprint/family_bp.py`）：`member_add` 中 `role=admin` 要求当前用户是超管，
否则 403；前端「家谱管理员」选项仅对超管显示。

**验证**：家谱管理员授予 admin → 403；超管走 `/api/admin/families/<fid>/members/<uid>` → 200。

### 12. 成员名单泄露手机号

**修改**：`member_list` 对 `member` 角色移除 `phone` 字段；前端非管理员不显示手机列与名单表格。

**验证**：普通成员返回项无 `phone` 键；管理员仍有。

### 13. 静态资源被 `no-store`

**修改**（`server/app.py`）：`/api/*` 与 HTML → `no-cache, no-store`；
`/assets/*` → `public, max-age=31536000, immutable`（文件名带内容哈希）。
同时补 `Content-Security-Policy`（`script-src 'self'`、`style-src 'self' 'unsafe-inline'` 等）。

**验证**：`/assets/*.js` 返回 `immutable`；`/api/health` 返回 `no-store`；响应带 CSP。

### 14. 三个「可点但无效」的配置项

**修改**：

- `privacy.mask_living`：真正实现——`server/service/privacy.py`，
  开启后普通用户读取在世成员时，生日/籍贯/安葬地/生平/备注返回空并带 `masked=true`，
  成员列表、详情、世系树三处均生效；管理员与超管不受影响。
- `access.public_read`、`member.scope`：从 `DEFAULTS` 与设置页移除，
  并新增 `OBSOLETE_KEYS` 在启动时删除旧库残留行（避免出现「开关存在但无效」）。

**验证**：开启后普通用户看不到在世者生日、管理员可见；设置页已无这两个开关。

## 四、批次 3：数据正确性（P2）

### 15. 参数错误掉 500

**修改**：新增 `server/service/valid.py`（`to_int` / `to_optional_id` / `to_id_list` / `page_args`），
在成员、婚姻、亲子、分支、事件、资源、日志、分页等入口统一校验；
另在 `app.py` 增加 `sqlite3.IntegrityError → 400` 兜底（区分 UNIQUE / FK / CHECK 文案）。

**验证**：`generation='abc'`、`type=99`、`page='abc'`、`logs?limit='abc'`、上传 `type=99`、
婚姻双方同一人，全部 400。

### 16. 空字符串写入整型外键

**修改**：所有外键型入参走 `to_optional_id()`，空串/0 → `NULL`。

**验证**：提交 `branch_id=''` 后库内 `branch_id IS NULL`。

### 17. 亲子关系无环检测，前端无穷递归

**修改**：

- 后端 `pc_create` / `pc_update` 写入前做 DFS：若 `child` 已是 `parent` 的祖先则拒绝；
- 前端 `web/src/pedigree/layout.ts`：`filterLine` 改为迭代 + `visited`；
  `subtreeWidth` / `place` 增加 memo 与在栈检测，遇环即止，不再栈溢出。

**验证**：A→B 后登记 B→A 返回 400 且未入库；环数据下世系树仍可渲染。

### 18. 万能路由吞掉 `/api/*` 404

**修改**（`server/app.py`）：`/<path:path>` 命中 `api/` 前缀时返回 JSON 404。

**验证**：`GET /api/not-exists` → 404 JSON。

### 19. 导入不重映射 ID，导出→导入不可闭环

**修改**（`server/blueprint/io_bp.py`）：

- 全部源 `id` 丢弃，建立 `branch/person/event/resource/marriage/parentchild` 六张映射表，
  关系表改写为新 ID 后入库；无法映射的行计入 `skipped` 而不是写悬空引用；
- 分支父子关系第二遍补齐，避免顺序依赖；
- 资源重新生成 `fid`，ZIP 内 `resources/` 原件解出写入 `uploads/<slug>/` 并更新 `storage_path`；
- `storage.default_strategy` 真正参与（`append` / `overwrite`），非法取值 400；
- 整个导入包在 `transaction()` 内，中途异常整体回滚。

**验证**：源数据 `person.id=901/902`、`spouse1_id=901` 导入后，婚姻指向新 ID 且同属目标库；
导出包可再次导入（二次闭环 3 人 1 婚 1 亲子）；ZIP 导入后资源文件确实落在上传目录。

### 20. `INSERT OR IGNORE` 后无条件计数

**修改**：改为逐条插入并统计实际入库行数，返回值新增 `imported` 明细
（`data.imported = {person: n, marriage: n, ..., skipped: n}`），
`data.person` 等仍为导入后总量，保持旧字段兼容。

### 21. GEDCOM 导入世代恒为 1

**修改**：`_gedcom_generations()` 先由 FAM 结构建父子图，再从无父母者 BFS 推层；
环路兜底为 1 世。

**验证**：三代 GEDCOM 导入后 `generation = [1, 2, 3]`。

### 22. `execute()` 逐句提交，业务无事务

**修改**（`server/db/conn.py`）：

- 连接改为 `isolation_level=None`（显式事务）；
- 新增 `transaction()` 上下文（嵌套安全、`BEGIN IMMEDIATE`、异常回滚）；
- 事务内 `execute()` 不再各自提交；
- 已包裹：`create_family`、`delete_family`、`delete_user`、`person_delete`、`event_delete`、
  `resource_delete`、`pc_create`、`branch_create/update/delete`、`branch_assign_members`、`import_data`。
- `branch_update` 改为「先校验全部成员归属，再进事务」，
  不再出现「清空归属后写回失败」的半成品。

**验证**：提交含不存在成员的 `person_ids` → 400，原分支归属保持不变。

### 23. 设置缓存无 TTL

**修改**（`server/service/settings.py`）：进程内缓存 + 30 秒 TTL + PID 校验（fork 安全），
写入即失效。多 worker 下最迟 30 秒自愈，不再出现「改完策略部分请求仍走旧值」。

### 24. 备份线程多进程重复、静默失败

**修改**（`server/service/backup.py`）：

- `data/backups/backup.lock` 存 PID，仅抢到锁的进程起定时线程；PID 已退出则自动接管；
- 文件名精确到毫秒并带 PID，避免同秒覆盖；
- 失败走 `logger.exception`，并记录 `status()`（最近成功/失败时间）；
- 清理残留的临时 `db_*.db`。

**验证**：连续两次备份文件名不同；多 worker 场景仅一个进程写日志（启动日志可确认）。

### 25. 无 logging 配置，`log/*.log` 为 0 字节

**修改**（`server/app.py: setup_logging`）：`log/server.log`（5MB × 3 轮转）+ 控制台，
格式含时间/级别/PID/模块。启动、迁移、备份、审计异常都会留痕。

### 26. 删除用户/家谱留下不可管状态与磁盘残留

## 七、升级须知（行为变化）

1. **首次启动口令不再固定**：新库随机生成 `admin` 口令，仅控制台打印一次；
   已有库不受影响，但 `admin` 的 `must_change_pwd` 若为 1，登录后必须先改密才能使用其他页面。
2. **首登强制改密由后端拦截**：未改密前业务接口返回 `403/4031`，前端自动跳转个人中心。
3. **改密会踢掉所有其他会话**：改密/重置密码后，旧 Cookie 立即失效（需重新登录）。
4. **家谱管理员不能再授予他人「家谱管理员」**：该操作仅超管可做（超管后台仍可用）。
5. **设置页少了两个开关**：`access.public_read`、`member.scope` 已下线（从未生效）；
   新增 `security.trusted_proxies`、`storage.default_strategy`。
6. **旧库首次启动会自动迁移**（补外键 + 清理悬空引用），建议升级前复制一份 `data/app.db`。
   迁移日志在 `log/server.log`，关键字 `[migrate]`。
7. **列表 `size` 上限为 500**：超过按 500 返回；非数字仍为 400。
8. **导入会重映射 ID**：同一份数据可以重复导入；不再保留源 ID 与源 `fid`。
